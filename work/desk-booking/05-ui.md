option B's zone list as the "Change a desk" picker and option B's occupancy table under A's heat grid; ST-BK-8 Best desk

## 0. Rules for every screen

### 0.1 Tokens (base only, B2.20 / B7.5; css prefix `dsk`)
| Use | Token (CSS variable) |
|---|---|
| Page background / card surface | `--dsk-background` / `--dsk-surface` |
| Card and table lines; strong line (focus of a selected day) | `--dsk-border` / `--dsk-border-strong` |
| Text: main, secondary, hints | `--dsk-text-primary`, `--dsk-text-secondary`, `--dsk-text-muted` |
| Primary buttons, selected day, "your desk", checked-in tick | `--dsk-accent`, hover `--dsk-accent-hover` |
| Selected chip, today column, tinted "checked in" card, reason tag fill | `--dsk-accent-soft`, edge `--dsk-accent-border` |
| Status badges | `--dsk-badge-bg`, `--dsk-badge-text` |
| Refusals, wrong desk, "15 minutes left" note edge | `--dsk-danger` |
| Radius | `--dsk-radius-sm` 6 (chips, badges), `--dsk-radius-md` 8 (buttons, inputs, day cells), `--dsk-radius-lg` 12 (cards, dialogs) |

- No shadows: cards and dialogs use a 1 px `--dsk-border` line; the base `shadows.card` token is not used on DeskBook screens.
- Text 13 px body, 12 px hints, 15 px card titles, 20 px page title; weights 400 and 500 only (headings 500). Desk codes in
  a monospace stack at the same size, weight 500.
- Compact spacing: 8 px inside rows, 12 px between fields, 16 px between cards, 16 px page padding (12 px at 360 px).
- Heat-grid cells mix `--dsk-accent` into `--dsk-surface` in steps (`color-mix(in srgb, var(--dsk-accent) N%, var(--dsk-surface))`);
  text on cells of 60 % and more uses the theme's `contrastText` (B7.4). No fixed hex anywhere (B7.8).
- There is no warning or success colour in the base: "Kept until", "15 minutes left" and the wrong-desk note use the
  neutral note style (surface, `--dsk-border-strong` left edge 3 px, icon) and `--dsk-danger` only for the wrong-desk and
  refusal edges. Meaning never relies on colour alone: every state also has an icon and words.
- Focus ring for the keyboard only: `:focus-visible { outline: 2px solid var(--dsk-accent); outline-offset: 2px }`; no
  ring on mouse click.

### 0.2 Shared behaviour
- Times are shown in the office's timezone from the answer (`Booking.timezone`, `BookableOffice.timezone`); the SPA never
  computes cut-offs or deadlines (05-architecture 8.4). Format: `10:00`, days `Tue 3 Nov`, `Today`, `Tomorrow`.
- Status words (P5) everywhere: BOOKED "Booked", CHECKED_IN "Checked in", COMPLETED "Completed", NO_SHOW "No-show",
  RELEASED_AFTER_HOLD "Released after hold", CANCELLED "Cancelled". Parts: FULL_DAY "Full day", MORNING "Morning",
  AFTERNOON "Afternoon".
- Errors: the SPA maps every problem `code` to a key in section 9; unknown codes and 5xx show `common.error.generic`
  with the request id (B2.12). 401/440 show the base session-expired screen (B2.16); a pending booking shows
  `booking.error.notSavedSignIn` after sign-in (AC17.3).
- Every write button is disabled while its call runs and shows a spinner inside the button (double click AC5.4, AC7.7).
  `createBookings` and `createBooking` send one new `Idempotency-Key` (UUID, 36 characters, allowed by the 16-64
  `[A-Za-z0-9_-]` rule) per press; a retry of the same press (network loss) reuses it, so nothing is booked twice.
- Mutations invalidate `today`, `myBookings`, `freeDesks`, `calendar` (05-architecture 6.2).
- Success feedback uses the base `AppToast` (B2.27), success 4 s, errors stay 8 s.
- Names of other people never appear on desks, in free lists or reports (R39, D2). Managers see their direct reports only.
- Screen width: the base shell keeps the 72 px icon rail at 360 px (journeys Q44; slide-over is ST-EN-3, R1), so every
  screen is specified for a 288 px content column. Touch targets at least 40 x 40 px at 360 px.

## 1. S1 Today `/dashboard`
Stories: ST-BK-11, ST-BK-12, ST-BK-15 DayStrip (D6), ST-CI-1, ST-CI-7, ST-NT-2 (reminder note), ST-PP-4, ST-EN-1 (MVP); ST-BK-16 usual desk card
(R1; MVP Today shows the head button, today's card, the two-week strip and the tomorrow card). Replaces the base dashboard cards (B2.10). Entry: sidebar "Today", `/` redirect, login.

### Layout (desktop, top to bottom)
1. Page head: title "Good morning, {firstName}" (or afternoon/evening by office time), subtitle "{weekday} {date} · {office} office, {time}";
   right: primary button "Plan my days" (opens S2).
2. Admin only: people-copy warning banner (when `syncBanner.severity` = WARNING).
3. Release note (when `releasedToday` present).
4. `TodayDeskCard` for today.
5. Card "Your next two weeks" (MVP) with hint "Each day is its own booking" and `DayStrip`: 14 tiles, today first, from
   `getToday.nextTwoWeeks` (no second call).
6. Two cards side by side: "Your usual desk" and "{office} tomorrow".

### Fields
| UI | Source |
|---|---|
| First name, office for subtitle | `getMyProfile.displayName` (first word); office = `getToday.tomorrow.officeName` (home office) |
| Today's booking: desk code, zone, floor, office, part, status, deadline, deadlineKind, holdAvailable, allowedActions, checkedInAt, version | `getToday.bookings[0]` when its `date` = office today (`Booking.deskCode`, `zoneName`, `floorName`, `officeName`, `part`, `status`, `deadline`, `deadlineKind`, `holdAvailable`, `allowedActions`, `checkedInAt`, `checkInOpensAt`, `version`) |
| Desk features on the card | not in `Booking` (Q116) - hidden until the field exists |
| Day strip tiles (MVP) | `getToday.nextTwoWeeks[]` (`TwoWeekDay`: `date`, `state`, `booking`), 14 items, soonest first, her own bookings only; `state` BOOKED -> booked tile with `booking.deskCode`, `booking.part`, `booking.status` and `booking.id` for the link; BOOKABLE -> "Add day" tile; CLOSED -> greyed tile `today.strip.closed`, no action; OUTSIDE_WINDOW -> greyed tile `today.strip.outside`, no action. No `listMyBookings` or `getBookingCalendar` call for the strip. |
| Release note | `getToday.releasedToday.releasedAt`, `.kind`, `.canRebookToday`, `.officeName` |
| Usual desk card (R1) | `getToday.usualDesk` (code, zone; absent with fewer than 3 bookings in 60 days, Q97) - no card when absent; floor and features need the same fields as a `FreeDesk` (Q116) |
| Tomorrow card | `getToday.tomorrow.freeDesks`, `.officeName`, `.date`; "of M" needs capacity (Q116), until then `today.tomorrow.free` |
| Admin banner | `getToday.syncBanner.lastGoodCopyAt`, `.daysSinceLastGoodCopy`, `.severity` |

| Action | Operation | Result |
|---|---|---|

| Running late, keep until {holdTime} | `holdBooking` (If-Match) | badge "Kept until {time}", button replaced by hint `checkin.card.keptHint`; toast `checkin.toast.held` |

| Booked tile (`state` BOOKED) | none (navigates to S4 `/bookings?focus=<booking.id>`) | S4 with the row focused |

| Book it (usual desk card, R1) | none (navigates to S2 with the next free day picked; `proposeDesks` then proposes the usual desk) | S2 |
| Book a desk for the rest of today (release note) | none (navigates to S2 with today picked) | S2 |
| Banner "Open People sync" (admin) | none (Settings > People sync, R1) | hidden in MVP when the tab does not exist |

### TodayDeskCard states (exact text)
| State | Condition | Shows |
|---|---|---|
| No desk today | no booking for today | title `today.card.title`, text `today.card.noDesk`, primary `today.card.bookToday` (hidden when no part of today is bookable) |
| Booked, check-in not open | `CHECK_IN` not in `allowedActions`, now before `checkInOpensAt` | badge Booked; Check in disabled with `checkin.card.opensAt` under it |
| Booked, window open | `CHECK_IN` in `allowedActions` | badge Booked; primary "Check in"; secondary `checkin.card.runningLate` when `holdAvailable`; note `checkin.card.deadlineNote` |
| Last 15 minutes | now >= deadline - 15 min and not checked in | note in danger edge `checkin.card.lastMinutes` above the buttons |
| Late booking | `deadlineKind` = LATE | note `checkin.card.lateNote` instead of the deadline note |
| Kept | `deadlineKind` = HOLD | badge `checkin.badge.keptUntil`; hint `checkin.card.keptHint`; note `checkin.card.deadlineNote` with the hold time |
| Checked in | status CHECKED_IN | tinted card, badge "Checked in {time}", line `checkin.card.checkedIn`; no buttons |
| Released | no booking today and `releasedToday` present | card shows `today.card.noDesk`; the release note above explains |

### Page states
| State | Text / behaviour |
|---|---|
| Loading | Skeleton: head line, one card 120 px, strip of 14 tiles, two small cards; no spinner text |
| Error (`getToday` fails) | card `common.error.loadTitle` + `common.error.loadText` + button `common.retry` |
| No bookings at all | TodayDeskCard "No desk today"; DayStrip tiles are "Add day" (BOOKABLE), closed or outside-window, none booked; extra line `today.empty.firstTime` |
| Strip, no bookable day | every tile CLOSED or OUTSIDE_WINDOW or BOOKED: no "Add day" tile; line `today.strip.noneBookable` under the strip |
| Strip with `getToday` error | the strip is part of the `getToday` response: it shows the page error card with the rest, never a strip of its own error |
| Release note | `today.released.noShow` or `today.released.afterHold`; then `today.released.rebook` with link `today.released.rebookLink` when `canRebookToday`, else `today.released.noRebook` |
| Profile not ready | `getMyProfile.profileReady` false: note `access.profileNotReady.title` + `access.profileNotReady.text`; Plan my days and Add day disabled with that note as their description; Today and My bookings stay usable (ST-PP-4) |
| No role | route guard sends to S6 No access |
| Admin banner | `today.syncBanner.warning` |
| Usual desk taken that day (R1) | card line `today.usual.taken` + button `today.usual.proposal` (opens S2) |
| Long text | office and zone names wrap to two lines then ellipsis with full text in `title` |

### Roles
Employee and manager: as above. Admin: same plus the sync banner (field absent for others, AC17.4). Nobody sees other people.

### 360 px
Head: title on one line (ellipsis), "Plan my days" becomes a full-width button under the subtitle. TodayDeskCard stacks:
desk code 20 px, place, then full-width "Check in" (48 px high) and full-width "Running late". DayStrip scrolls sideways
(14 tiles 88 px wide, snap per tile, today first, date and weekday on every tile); the two small cards stack.

### Keyboard order and screen-reader labels
Order: skip link to main -> Plan my days -> banner link (admin) -> release note link -> Check in -> Running late -> strip
tiles left to right (closed and outside-window tiles are skipped) -> usual desk card -> tomorrow card. Arrow keys move inside the strip (roving tabindex, one tab stop).
- TodayDeskCard is a `section` with `aria-labelledby` the card title; status change after Check in or hold is announced
  through an `aria-live="polite"` region with the toast text.
- Disabled Check in keeps focus and has `aria-describedby` to the opens-at text.
- Strip tiles: booked tile `aria-label` `today.strip.bookedAria`; add tile `today.strip.addAria`; closed tile `today.strip.closedAria` and
  outside-window tile `today.strip.outsideAria` are plain text, not buttons (state is also written, never colour only).
- Tomorrow bar is a `meter` with `aria-label` `today.tomorrow.aria`.

## 2. S2 Plan my days `/book`
Stories: ST-BK-13 Plan my days, ST-BK-14 Change a desk, ST-BK-8 Best desk (MVP by D5), ST-BK-1, ST-BK-5, ST-BK-6, ST-BK-7;
zone and feature options need an employee operation (Q115). Sidebar item stays "Book a desk" (journeys navigation); page
title is "Plan my days". Entry: sidebar, S1 buttons and tiles, S4 empty state.

### Layout
Desktop: two cards side by side (left 55 %, right 45 %).
- Left card "Choose": Office select, Part of the day segmented control (Full day / Morning / Afternoon), Zone select,
  "Must have" feature chips; divider; heading "Days" with hint `booking.plan.horizonHint`; `DayPickerGrid` (this week
  and next week, Mon-Fri; header row of weekday names).
- Right card "Your desks": office name on the right of the title; one `DeskProposalRow` per picked day in date order;
  divider; full-width primary "Book {n} days"; hint `booking.plan.separateHint`.
- Above both cards: the release note of S1 when present (ST-BK-12), and the stale-data note (R1, ST-BK-3).

### Fields
| UI | Source |
|---|---|
| Office options | `listBookableOffices` rows `id`, `name`, `city`; default home office (`getToday.tomorrow.officeId`), remembered office is R1 (ST-BK-2) |
| Day cells: date, bookable, reason | `getBookingCalendar(officeId)` `days[].date`, `days[].parts[part].bookable`, `.reason` (PAST, NON_WORKING_DAY, CLOSED_DAY, BEYOND_HORIZON, PART_ENDED); `horizonDays` for the hint |
| Day cell free count | not in `CalendarDay` (Q116); until then the cell shows no count |
| Own booking on a day | `listMyBookings` (same window) `date`, `deskCode` |
| Zone options, feature chips | no employee operation lists them (Q115): `listZones`/`listFeatures` are admin-only; hidden until one exists, `proposeDesks` is then called without zone and features |
| Proposed desk per day: desk id, code, zone, floor, features, reason | `proposeDesks` (request: days 1-14 distinct, `part`, optional zone, features) answer per day: desk (code, floor, zone, features) + reason `USUAL_DESK`, `SAME_ZONE`, `MATCHES_CHOICES`, `FIRST_FREE`, or no desk (05-security row 43) |
| Change picker list | `listFreeDesks(officeId, date, part, page, size)` rows `id`, `code`, `floorName`, `zoneName`, `features`; `totalFree`; `asOf` |

### Actions
| Action | Operation | Result |
|---|---|---|
| Change office | `getBookingCalendar`, proposals reload | picked days kept when bookable in the new office, others dropped with toast `booking.plan.daysDropped` |
| Change part of the day | proposals reload | cells re-evaluate the part's `bookable` |
| Toggle a day | `proposeDesks` for all picked days (debounced 400 ms; limit 20 per minute, so one call per change, not per day) | row added or removed on the right; days with a "Your choice" desk keep it |
| Change (per day) | `listFreeDesks` for that day | opens S2b Change picker |
| Book {n} days | `createBookings` once (days with desk and part, one `Idempotency-Key`; Q98 recommends one request) | S3 with the per-day result BOOKED / REPICKED / FAILED |

### DayPickerGrid cell states (exact text under the date)
| State | Condition | Text | Interactive |
|---|---|---|---|
| Free to pick | `bookable` true | `booking.day.free` ("{n} free") when the count exists, else empty | yes, `aria-pressed` false |
| Picked | selected | `booking.day.comingIn` with a tick | yes, `aria-pressed` true |
| Already booked | own booking that day | desk code | no; link to S4 row |
| Past | reason PAST | `booking.day.past` | no |
| Weekend / non-working | NON_WORKING_DAY | weekend cells are not drawn (Mon-Fri grid); a non-working weekday shows `booking.day.nonWorking` | no |
| Office closed | CLOSED_DAY | `booking.day.closed` | no |
| Not open yet | BEYOND_HORIZON, or a grid day after the last calendar day | `booking.day.opensOn` ("Opens {weekday}" = that date minus `horizonDays`, display only) | no |
| Part ended (today) | PART_ENDED | `booking.day.partEnded` | no |
Disabled cells use `aria-disabled="true"` and stay focusable so the reason is read.

### DeskProposalRow states
| State | Shows |
|---|---|
| Proposal | day label, part; desk code + `ReasonTag` (`booking.reason.USUAL_DESK` with spark icon, `booking.reason.SAME_ZONE`, `booking.reason.MATCHES_CHOICES`, `booking.reason.FIRST_FREE`, or `booking.reason.yourChoice` after Change); "{zone} · Floor {floor} · {features or booking.desk.noExtras}"; ghost button "Change" |
| Loading | skeleton line in the row |
| No free desk | `booking.plan.noDesk` and no Change button; the day does not count in "Book {n} days" |
| Today after release | extra line `booking.plan.lateNote` (P1) |
| Picker open | button text "Close" |

### Page states
| State | Text |
|---|---|
| Nothing picked | right card `booking.plan.pickHint`; Book button disabled, label `booking.plan.bookNone` |
| Loading calendar | grid skeleton (10 cells) |
| Calendar error | `common.error.loadTitle` + retry |
| No open office | whole page: `booking.empty.noOffices` (employee) / `booking.empty.noOfficesAdmin` with button `office.list.createFirst` (admin) (AC1.7) |
| All picked days have no desk | Book disabled, note `booking.plan.allFull` |
| Profile not ready | note `access.profileNotReady.title` + text at the top; Book disabled (ST-PP-4) |
| Already has bookings on picked days | cannot happen (those cells are not pickable); if the server says `ALREADY_BOOKED_THAT_DAY` see section 9 |
| Stale data (R1) | note `booking.stale` |
| Long zone names | wrap in the row; office select max 240 px with ellipsis |

### Roles
All roles the same; the list never shows reserved desks to people not on the access list (R1) and never names.
Admin sees the same page as an employee (A9).

### 360 px
One column: Office, Part (segmented, full width), Zone and Must have under a "More choices" disclosure (closed by
default); grid cells 48 px high with the date and a one-word state; "Your desks" card follows the grid; the Book button
is sticky at the bottom of the viewport (48 px, full width) while at least one day is picked.

### Keyboard and screen reader
Order: Office -> Part -> Zone -> feature chips -> grid (one tab stop; arrows move by day, Up/Down by week; Space or
Enter toggles) -> proposal rows (Change buttons in date order) -> Book.
- Grid is `role="grid"` with `aria-label` `booking.plan.gridAria`; each cell `aria-label` "Tuesday 3 November, 12 desks free, not
  selected" (key `booking.day.cellAria`) or with its reason.
- Right card is `aria-live="polite"`: adding a day announces `booking.plan.addedAria`.
- Chips are toggle buttons with `aria-pressed`. ReasonTag is plain text inside the row label.

## 2b. S2b Change a desk (dialog on S2; option B's zone list)

`listFreeDesks`. If the chosen desk is taken before she books (ST-BK-14), `createBookings` answers REPICKED or FAILED for

| Action | Operation | Result |
|---|---|---|
| Choose | none (local choice) | dialog closes, row shows the desk with tag `booking.reason.yourChoice`; focus returns to that row's Change button |
| Scroll to the end | `listFreeDesks` next page | rows appended |

## 3. S3 Booked (result page `/book/done`)
Stories: ST-BK-13 (result list), ST-BK-5 (AC5.1), ST-BK-6, ST-CI-6 (late note). Operation: the `createBookings` answer
(per day BOOKED, REPICKED with old and new desk code, FAILED with the problem code; 05-security 4.2a).

Layout: one card, max 640 px: tick icon, title `booking.done.title` ("You're booked for {n} days"), sub `booking.done.sub`;
`BookingResultList` (day, desk code, "{zone} · Floor {floor} · {office}", part, check-in deadline); refused days under

| UI | Source |
|---|---|
| Per booked day | `createBookings` day result with its `Booking` (`date`, `deskCode`, `zoneName`, `floorName`, `officeName`, `part`, `deadline`, `deadlineKind` |
| Per refused day | FAILED day's problem `code` (+ `existingBookingId`) mapped in section 10 |
| How check-in note | the first booking's `deadline` (office time); the hold time is not in `Booking` and `getBookingRules` is admin-only, so the note uses `booking.howCheckin.textNoHold` until a hold-until time is added (Q116) |
